Задача 2. Многошаговая регистрация и модель пользователя
Цель: реализовать регистрацию анкеты игрока через Telegram-диалог, проверку введённых данных и подготовку к постоянному хранению профилей. Использовать уже созданную архитектуру, не вводя параллельную систему состояний.

Сценарий регистрации:
1. /registry запускает диалог для конкретного Telegram userId.
2. Бот последовательно запрашивает имя → Steam URL → прайм-тайм → роль → игры.
3. Каждый ответ проверяется перед сохранением; при ошибке бот повторяет запрос, а состояние не меняется.
4. /back возвращает к предыдущему вопросу, /cancel отменяет регистрацию и очищает черновик.
5. После последнего корректного ответа данные передаются в модель User; черновик удаляется только после успешного сохранения анкеты (временное хранение допустимо до внедрения БД).
  - Разработчик 1 — логика бота и автомат состояний (основная часть реализована):
    - [x] Создать BotState, BotEvent, StateManager и TransitionTable для управления диалогом.
    - [x] Создать RegistrationSession — черновик анкеты с полями имени, Steam URL, прайм-тайма, роли и игр.
    - [x] Создать RegistrationHandler с методами запуска, продолжения и отмены регистрации и обработкой шагов через switch.
  - Разработчик 2 — проверка данных и профиль игрока:
    - [ ] Дописать RegistryMessageValidator: проверки имени, Steam URL, прайм-тайма, роли и игр; при ошибке возвращать понятную причину, не меняя этап регистрации. Добавить простые тесты.
    - [ ] Создать класс User: постоянная модель игрока (userId, имя, Steam URL, прайм-тайм, роль, игры), отдельная от временного RegistrationSession.
    - [ ] Опционально подключить БД (например, SQLite): сохранять завершённые анкеты и получать их после перезапуска бота. Если БД пока нет, предусмотреть простой временный способ сохранения готовых User в памяти.
